# 当前导览后台基线

## 1. 技术边界

- 入口：`index.html`
- 运行时：原生 JavaScript 单页应用，无需先迁移框架。
- 主要业务状态与渲染：`src/app.js`。
- 主要视觉样式：`src/styles.css`。
- 数据演示与持久化：`localStorage`，键名为 `guide.appData`。
- 当前项目已经具备业务交互，不应在视觉迁移阶段重写数据模型。

## 2. 当前一级导航与页面

当前一级导航：

- 导览任务
- 地图
- 语音

语音下的二级导航：

- 人设
- 插件

当前已实现的页面族：

- 导览任务列表、详情、新建 / 编辑三步流程
- 地图列表、详情、添加 / 编辑与删除确认
- 人设空状态、列表、详情、新建 / 编辑
- MCP 插件空状态、列表、详情、新建 / 编辑
- 账户菜单、语言切换、重置演示数据、退出登录
- 多类确认弹窗和 Toast

## 3. 当前已实现的复杂交互

- 表格行点击进入详情。
- 行内编辑和“更多”菜单。
- 删除二次确认。
- 表单字段校验与字段级错误提示。
- 地图选择器与搜索。
- 地图点位新增、拖拽、删除、朝向调整。
- 任务动作新增、删除、排序拖拽。
- 技能选择、插件多选、人设选择。
- MCP 插件刷新和工具标签展示。
- 页面底部固定步骤操作栏。
- localStorage 持久化和演示数据重置。

## 4. 当前视觉结构的主要特征

当前 CSS 已经有较清晰的基础体系：

- 白色页面背景。
- 黑 / 灰文字层级。
- 顶部导航 + 内容区结构。
- 轻量边框和分割线。
- 低圆角按钮、输入框、菜单和弹窗。
- 以表格、开放列表和分割线为主，不是卡片网格。
- 使用 SVG 图标和状态图标。

这意味着后续更适合做“设计系统替换和交互形态迁移”，而不是从零搭建新的后台。

## 5. 当前与目标稿的潜在差异类别

以下是迁移前的差异基线；目标形态已在 `interaction-matrix.md` v1.0 关闭为产品决策，不能再按“待核对”理解：

- 某些选择器当前是页面内展开列表，迁移目标已决策为 Select Dialog（地图）或 Popover（少量技能 / 插件）。
- 某些编辑流程当前使用整页；人设和地图点位继续独立页面，插件改为宽 Modal，依据是字段复杂度与画布上下文。
- 当前行操作菜单是轻量菜单，迁移目标统一为 Dropdown surface Popover，并按 Figma 195×48px / 12px Radius / 0.5px Border 语法对齐。
- 当前部分确认操作统一使用 Modal，迁移目标统一为 402px Confirm Modal 语法；具体 Prototype 连线因来源限制保持 BLOCKED。
- 当前地图 / 任务编排包含画布和拖拽，不能为了视觉相似而牺牲连续编辑上下文。

## 6. 不应被阶段 1 改动的内容

- 现有数据字段和 localStorage 结构。
- 现有路由 hash 规则。
- 现有任务、地图、人设、插件的业务校验。
- 现有拖拽和排序状态。
- 现有演示数据。
