2. Button / Icon button / Text button
3. Input / Select / Textarea / Checkbox / Radio / Toggle
4. Table / Row actions / More menu / Tags
5. Empty state
6. Modal / Confirm Modal / Alert / Toast
7. 导览任务列表
8. 地图列表与详情
9. 人设列表、创建、编辑、详情
10. MCP 插件列表、添加、编辑、详情
11. 导览任务新建 / 编辑 / 点位 / 动作编排
12. 响应式、键盘、焦点和回归测试

## 2. 页面级验收

每个页面都要检查：

- 页面壳是否与目标稿同一设计语言。
- 标题、说明、主按钮层级是否正确。
- 默认、Hover、Focus、Disabled、Error、Loading 状态是否齐全。
- 表格行和操作列是否与目标模式一致。
- 空状态是否使用目标稿的同类结构。
- Modal / Popover / 独立页面的选择是否符合交互矩阵。
- 关闭、取消、返回、Esc 和点击外部的行为是否明确。
- 长文本和窄屏是否可用。
- 业务数据、路由、localStorage 和拖拽行为是否保持。

## 3. 第一批建议验收页面

优先选三张代表不同复杂度的页面：

1. 导览任务列表：表格 + 主按钮 + 行操作 + 空状态。
2. 创建人设：目标稿已有同名样例，可验证表单和独立页面。
3. 添加插件：可验证 Modal、动态认证字段、错误反馈和 Toast。

这三张通过后，再迁移地图和多步骤任务编排页面。

## 4. 每次修改前的安全检查

- 确认只修改计划中的文件。
- 不改 localStorage key 和数据版本。
- 不删除现有事件处理器。
- 不在设计审计阶段引入新的运行时依赖。
- 修改后至少验证一级导航、列表行点击、一个表单提交和一个确认弹窗。
