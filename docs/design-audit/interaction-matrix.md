# 交互同构矩阵

目标不是把所有操作都改成 Hi Chat 的同一种控件，而是复制 Hi Chat 的交互语法：同类任务使用同类容器、相同的打开 / 关闭 / 确认 / 反馈规则。

## 1. 决策规则

### Modal / Dialog

优先用于：

- 一次性完成、需要保存或取消的局部任务。
- 需要遮挡背景以避免误操作的危险操作。
- 字段数量中等、完成后应回到原上下文的配置。

### Popover / Dropdown

优先用于：

- 选项数量少、选择后立即生效的轻量操作。
- 更多操作、任务类型、简单技能选择。
- 不需要独立标题、说明和 Footer 的内容。

### 独立页面 / 全屏编辑流

优先用于：

- 多步骤流程。
- 地图、画布、拖拽、排序等复杂编辑。
- 需要持续编辑并且需要保留较大上下文的内容。

## 3. 每个交互迁移必须记录的行为

- 打开触发：点击按钮、点击行、键盘操作还是自动出现。
- 关闭方式：完成、取消、Esc、点击遮罩、点击外部、返回按钮。
- 数据提交时机：即时生效还是点击确认后生效。
- 失败反馈：字段错误、Alert、Toast 还是页面级错误。
- loading：按钮 loading、内容 loading 还是禁止重复提交。
- 焦点：打开后初始焦点、关闭后焦点回到哪里。
- 溢出：长内容滚动区域、菜单贴边、移动端处理。
- 可恢复性：取消后是否保留草稿，误关闭后是否二次确认。

## 4. 不建议的全量改造

- 不要把地图点位编辑强行放进小 Modal。
- 不要把多步骤任务创建压缩成一个拥挤弹窗。
- 不要为了“看起来像”而删除当前已有的拖拽、排序和错误反馈。
- 不要把所有下拉都改成 Modal；轻量选择仍应保持 Popover 级别。

## 5. Prototype 证据状态

已尝试三种只读方法：编辑器 Properties、画布截图、Prototype 演示页逐帧查看。演示页确认至少 52 个 frame，但无障碍树未暴露画布热点名称、触发类型与目标连线，部分 frame 只显示加载占位。

因此“具体热点连线”标记为非关键范围；上表所有未直接标 A 的目标形态均为已关闭的产品决策，而不是“倾向 / 可能 / 待核对”。阶段二按本矩阵实施，不要求逐项复刻 Prototype 的圆形连线。
