# Hi Chat Design → 导览后台：具体设计规范 v1.15

> 这是一份面向后续开发的单一设计规范入口。它把视觉、布局、组件、状态、交互和页面映射集中在一起。
>
> 规范状态：**阶段 1 v1.15，唯一实施入口**。A 为 Figma / 当前项目直接证据，B 为明确实施映射，P 为产品决策；Prototype 圆形连线细节不属于本规范的实施前置条件。任何 B/P 都不得被描述为 Figma 原始读数；后续若取得新证据，只更新本文件的变更记录和对应 Token。

## 0. 设计目标与边界

### 目标

让导览后台在以下方面与 Hi Chat Design 建立同一套产品语言：

- 页面壳、导航、标题区、表格、表单、空状态、按钮、弹窗、Alert、Popover 的外观。
- 同类操作使用同类容器和反馈方式。
- Hover、Focus、Selected、Disabled、Loading、Error 等状态一致。
- 保留导览业务所需的地图、点位、路径和任务编排能力。

### 边界

- 复制设计语言和交互语法，不复制 Hi Chat 的业务内容。
- 所有业务文本、地图数据、点位数据、任务动作、语音人设和 MCP 插件数据仍属于导览后台。
- 不将地图画布、多步骤任务编排强行压缩成小弹窗。
- 不把 Figma 截图作为静态 UI；控件和文字必须继续由代码渲染。

## 2. 页面与容器规范

### 2.1 基准画布

| 项目 | 规范 |
|---|---:|
| Figma 首页基准尺寸 | 1440 × 870（A） |
| 桌面最小可用宽度 | 1024px（B） |
| 页面左右边距 | 48px（B） |
| 页面内容宽度 | 填满页面可用宽度，不设置最大宽度（P：HiChat 当前页面参考） |
| 小屏左右边距 | 24px（B） |
| 顶部导航高度 | 64px（B：实施映射，Figma 未暴露精确值） |
| 页面标题区最小高度 | 62px（B） |
| 标题区到首个内容区 | 32px（B） |
| 主要区块之间 | 32–40px（B） |
| 工作区背景 | `#EDF7FF → #FBFCFF → #F3F1FF` 青蓝至近白至淡紫的线性渐变（B：Hi Chat Hub 全页视觉参考映射） |
| 工作区面板 | 每个页面的顶层工作区：纯白、无外描边；20px 为实施圆角；内容不足一屏时，面板最小高度覆盖可见内容区（A/B：Hi Chat Hub 空列表视觉参考 + 实施映射） |

页面应使用开放布局、留白和独立白色工作区作为主要组织方式；列表、空态、详情与加载态使用纯白无描边的全宽工作区，并在内容不足时延展至可见内容区底部。编辑页在渐变画布中以多个独立白色卡片组织模块，操作区也使用独立白色卡片；不以大面积外描边或密集分割线组织页面。仅在同一张动作配置卡内，允许使用极弱分隔线区分相邻动作段。

### 2.2 页面壳

```text
App shell
├─ Topbar（固定文档流，不悬浮）
│  ├─ Brand
│  ├─ 一级导航
│  └─ 账户入口
└─ Main content
   ├─ Page heading（标题 + 说明 + 主操作）
   └─ Page body（table / form / preview / editor）
```

- 顶部导航可直接置于工作区渐变上，不使用结构性分割线；当前一级导航仍使用文字变深 + 底部 2px active indicator。
- 页面标题左对齐；主操作位于标题区右侧。
- 详情页和表单页的返回按钮与标题在同一水平线。
- 复杂编辑页的操作按钮正常出现在内容末尾，置于独立白色操作卡片中，不吸附视口底部。
- 插件列表在没有数据时只在空态底部提供“添加插件”；有数据后才在标题区提供同一主操作，避免重复入口。
- 添加、编辑插件使用独立表单页；字段单列排列，认证方式使用带勾选状态的 Popover Select，不使用浏览器原生 Select。
- 插件空态使用中性灰色插头线稿，与旧版导览后台的空态图标语义一致。

### 2.3 一级导航与导览任务侧边导航

- 顶部一级导航仅保留 `导览任务`、`机器人`。任务、地图、人设、知识库、插件及其详情和编辑页均归属“导览任务”，顶部保持该项选中。机器人使用无顶部天线的线性图标。
- “导览任务”下统一展示侧边导航：`流程配置`、`资源管理`；资源管理为固定展开的分组标题，不提供点击、展开 / 收起按钮或箭头。子项依次为 `地图`、`人设`、`知识库`、`插件管理`。
- 点击侧边导航切换内容；直接进入详情或编辑地址时，对应资源保持选中。
- 二级导航宽度：184px（B）。
- 二级导航与内容之间间距：28px（B）。
- 二级导航不使用右侧分割线；每项带对应的线性图标。
- 选中项使用白色圆角表面、深色文字和 600 字重；默认与 Hover 项保持透明或轻白表面。
- 小屏幕将侧边导航转为内容上方的两行导航，资源子项独立一行；子项始终展示，空间不足时在该行横向滚动。
- 机器人列表不展示导览侧边导航；机器人监控详情为独立页面，不展示全站导航。
- 插件管理使用独立的资源导航入口，位于知识库下方，与地图、人设和知识库同级；人设列表不再重复展示入口。知识库当前仅提供导航入口及“知识库管理暂未开放”占位页。

### 3.2 使用规则

- 默认组件和内容表面保持纯白；不能把白色擅自改成米色、奶油色或暖灰色。
- 后台页面壳统一使用 `--gradient-workspace`；按钮、表格、输入框、Select 和表单字段保持纯白或中性表面，不在控件本身增加渐变。
- 整体仍以白色表面和中性文本为主；`#6E63FF` 只用于主操作、当前导航指示、品牌图标、选中控件和聚焦反馈，不大面积铺色。
- 主按钮使用紫色实心；危险按钮使用语义红色，不与主操作混用。
- 错误色只用于错误边框、错误文案和危险状态，不用于大面积装饰。
- 描边对比度优先满足可读性；Figma 中“描边颜色需加重”的评论视为高优先级复核项。

### 3.3 全局颜色使用约束（v1.12）

以下为本项目实施规则（B/P），适用于导览后台全部页面及共享 UI 组件。代码变量使用 `--guide-` 前缀，唯一色值来源为 `packages/ui/src/tokens.css`；页面 CSS 不另建配色表，不直接写十六进制或 RGB 颜色。

| 用途 | 实际 CSS Token | 使用规则 |
|---|---|---|
| 主操作、选中、焦点 | `--guide-color-primary` / `primary-hover` / `primary-soft` | 主按钮、Slider、Checkbox、Radio、音色选中、任务选中、当前流程均使用紫色 `#6E63FF`；原生控件也必须继承主色。 |
| 弱品牌背景 | `--guide-color-primary-tint` | 少量任务卡片、弱强调；不替代白色内容面。 |
| 页面与内容表面 | `--guide-gradient-workspace`、`--guide-color-page` / `surface-subtle` / `surface-hover` | 工作区使用既有渐变，内容面白色，次级面和 Hover 为中性灰。独立机器人页沿用此规则，顶部保持白色。 |
| 文字层级 | `--guide-color-text-strong` / `text` / `text-muted` / `text-placeholder` | 标题、正文、辅助文本、占位文字分别复用对应中性色；不能用偏绿色灰阶。 |
| 边框、插图 | `--guide-color-border` / `border-hover` / `divider` / `illustration` / `illustration-detail` | 结构线和空态线稿使用中性灰，不使用状态色装饰。 |
| 成功、正常状态 | `--guide-color-success` / `success-soft` | 绿色仅表示已连接、直播可用、定位正常、下发成功等结果；不能作为普通控件主题色。 |
| 警示、等待状态 | `--guide-color-warning` / `warning-soft` | 未连接、未定位、定位中、暂停和需注意的信息；同时提供文字，不能仅靠色彩区分。 |
| 错误和危险操作 | `--guide-color-danger` / `danger-hover` / `danger-soft` / `danger-focus` | 定位失败、错误提示、删除和停止/结束操作；表单错误边框与焦点环使用同一红色体系。 |
| 信息、地图位置 | `--guide-color-info` / `info-soft` | 信息标签、地图中的机器人位置标记；导览路线和任务点位使用主色，起点用更深主色并标注“起点”。 |
| 禁用状态 | `--guide-color-disabled` / `disabled-surface` | 使用中性色与 disabled 属性，不把禁用控件标成成功或错误。 |
| 视频覆盖层 | `--guide-color-media-*`、`--guide-color-text-inverse` | 仅摄像头画面允许深色底、半透明黑色遮罩和白字，确保复杂画面上的可读性；不得外溢成页面深色主题。 |

- 同一种语义在按钮、标签、提示、地图、进度和原生控件中复用同一 Token；信息 Toast 的品牌紫色沿用现有共享组件规则。
- 状态必须同时有文字、图标或标签；选中态与连接成功态分别用紫色和绿色表达。
- 地图底图、摄像头图片属于业务内容，其原始颜色不受 UI 主题替换影响。
- 机器人 Agent 设备端有独立深色运行界面，不在本次后台主题统一范围内；共享组件使用上述 Token。
- 本次检查覆盖后台主样式、机器人页及共享组件：统一原生控件 accent-color，收拢表单 Hover/错误、空态、标签、Toast、表格和地图覆盖层颜色。后续新增颜色须先定义语义 Token，再引用到页面。

## 4. 字体与排版规范

### 4.1 字体栈

```css
font-family: Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
```

这是 B：实施映射。Figma 只读面板未暴露字体文件名，因此真实字体仍为 BLOCKED，不得在验收中称为 Figma 实测。

### 4.2 类型 Token

| Token | 字号 | 字重 | 行高 | 用途 |
|---|---:|---:|---:|---|
| `type.page-title` | 28px | 650 | 1.25 | 页面标题、详情标题 |
| `type.section-title` | 22px | 600 | 1.4 | 空状态标题、Modal 标题 |
| `type.subsection` | 18px | 600 | 1.4 | 表单区块、任务区块标题 |
| `type.body` | 16px | 400 | 1.55 | 正文、表格值、表单值 |
| `type.body-strong` | 16px | 600 | 1.5 | 名称、强调值、主操作文字 |
| `type.label` | 16px | 600 | 1.4 | 字段标签、表单标题 |
| `type.caption` | 14px | 400 | 1.5 | 辅助说明、时间、表头 |
| `type.button` | 16px | 600 | 1 | Button 文本 |

规则：

- 所有 Button、Tab、Input、Select、Popover、表格单元格都显式声明字号，不能依赖浏览器默认值。
- 正文、标签、输入值、placeholder 和按钮统一使用 16px；辅助信息、时间和表头统一使用 14px。
- 标题与辅助说明之间默认间距 8–10px。
- 长文本使用自然换行；名称和表格单元格可截断，但必须通过 title 或详情页保留完整内容。

## 5. 间距、圆角、边框、阴影

### 5.1 间距 Token

基础单位为 4px：

`4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 40 / 48 / 64`

使用规则：

- 控件内水平留白：12px 或 16px。
- 字段标签与控件：8px。
- 字段之间：24px。
- 表单区块之间：40px。
- Modal 外层内边距：32px（A：Figma Modal）；内部区块间距按组件变体映射。
- 页面主内容边距：48px。
- 底部固定操作栏高度：72px。

### 5.2 圆角 Token

| Token | 值 | 用途 |
|---|---:|---|
| `radius-sm` | 12px | Input、Select、细粒度控件 |
| `radius-md` | 12px | Button、Popover、Table tag、菜单 |
| `radius-lg` | 32px | Modal、预览容器、编辑块 |
| `radius-workspace` | 20px（B） | 白色无描边编辑器、配置、空态和列表面板；移动端 14px |
| `radius-round` | 50% | 头像、点位标记、Toggle thumb |

`radius-workspace` 只用于 Figma 明确展示的大面积工作区容器，包括列表的外层面板；Input、Button、Tag、菜单和浮层仍遵循小圆角 Token，不把普通按钮做成胶囊。

### 5.3 阴影 Token

```css
--shadow-popover: 0 10px 24px rgb(0 0 0 / 10%);
--shadow-modal: 0 20px 60px rgb(0 0 0 / 12%);
--shadow-toast: 0 12px 16px -4px rgb(16 24 40 / 4%);
```

只用于浮层，不给普通工作区面板增加阴影或描边；白色工作区应依靠渐变画布和留白形成层级。

## 6. 基础组件规范

### 6.1 Button（Figma A 证据 + 实施映射）

| 变体 | 高度 | 内边距 | 背景 | 文字 |
|---|---:|---:|---|---|
| Primary | 44px | 0 18px（B：实施映射） | `#6E63FF` | `#FFFFFF` |
| Secondary | 44px | 0 18px | `#FFFFFF` | `#3E3E3E` |
| Text | 30px | 0 | transparent | `#4C4C4C` |
| Icon | 30×30px | 0 | transparent | 当前文字色 |
| Danger | 44px | 0 18px | `#B42318` | `#FFFFFF` |

状态：

- Primary Hover / Active：背景 `#5B52E8`。
- Secondary Hover：背景 `#F8F8F8`，边框加深。
- Text Hover：文字 `#111111`，可加 3px 下划线偏移。
- Disabled：背景 `#E5E5E5`，文字 `#999999`，禁止重复提交。
- Focus：2px `#6E63FF` outline，offset 2px；已是紫色背景的控件使用外环和 offset 保持可见。
- 图标与文字间距：12px（A：Button Gap）；不得沿用旧版 6px 猜测值。
- Figma 未暴露按钮文字字号、字体、圆角和完整 Variant 状态色；这些采用 B/P 实施映射，不能写成 Figma 原始证据。

### 6.2 Input / Select / Textarea

- 默认高度：44px。
- 默认边框：1px `#D9D9D9`。
- 圆角：12px。
- 水平内边距：14px。
- 文字：16px，颜色 `#303030`。
- Placeholder：14px，`#8A8A8A`。
- Hover：边框 `#A6A6A6`。
- Focus：边框 `#6E63FF` + 2px `rgb(110 99 255 / 15%)` 外描边。
- Error：边框 `#B42318`，下方 12px 错误文案。
- Textarea 默认最小高度：112px；动作播报文本域最小高度为 44px，并随内容扩展。

### 6.3 Radio / Checkbox / Toggle

- Checkbox / Radio 尺寸：15px。
- 选中色：`#6E63FF`。
- Toggle 尺寸：36×22px。
- Toggle 未选中背景：`#B7B7B7`；选中背景：`#6E63FF`。
- Toggle thumb：18px，白色，带轻微阴影。

### 6.4 Table

- 列表表格置于白色无描边工作区面板内；表格本身不增加描边、阴影或嵌套卡片。
- 表头最小高度：42px。
- 数据行最小高度：64px（A：`Table cell` Height Fixed 64px）。
- 单元格水平内边距：16px（A：`Table cell` Padding 16px）。
- 表格随可用宽度缩放，默认最小宽度为 560px；仅在容器低于最小宽度时在表格内部横向滚动，不使页面整体溢出。地图列表沿用该最小宽度，不单独设置 960px 宽度。
- 表头：14px、500 字重、`#777777`。
- 数据：16px、`#303030`。
- 数据行之间使用 `1px #F0F0F2` 弱分割线，最后一行不绘制尾部分割线；不再依靠行距模拟分隔。
- Row Hover：`#FAFAFA`。
- 名称列使用 600 字重。
- 任务、地图、人设、插件、机器人列表的操作列统一居中；编辑、删除、下发任务、实时监控等常用操作直接展示为等尺寸图标按钮，并通过悬停提示和无障碍名称标明用途，不收进“更多”菜单。
- 行点击进入详情时，行内按钮必须阻止事件冒泡，避免同时跳转。机器人整行点击或行聚焦后按 Enter / 空格进入实时监控；行内下发按钮通过鼠标或键盘触发时只打开下发弹窗。

### 6.5 Tag

- 高度：25–26px。
- 水平内边距：8px。
- 边框：1px `#DEDEDE`。
- 圆角：12px。
- 背景：`#F8F8F8`。
- 文字：14px，`#565656`。
- 超出列宽时截断；完整工具名放在 title / 详情页。

### 6.6 Empty state

- 默认最小高度：430–480px。
- 图标 / 插图在上，标题在下，说明再下，CTA 最后。
- 图标与标题间距：26px。
- 标题：22px、600 字重。
- 说明：14px、`#8A8A8A`，上方 10px。
- CTA：上方 28px。
- 空状态必须提供下一步动作：新建、添加或查看说明。

### 6.7 Popover / Dropdown

- 背景：白色。
- 边框：1px `#D9D9D9`。
- 圆角：12px。
- 阴影：`--shadow-popover`。
- 内边距：6px。
- 菜单项最小高度：32–36px。
- Hover：`#F3F3F3`。
- 打开后支持 Esc 关闭；点击外部关闭；选择后按业务规则立即生效或等待确认。
- 菜单靠近视口边缘时自动翻转，不允许被裁切。

### 6.8 Modal / Confirm Modal

| 类型 | 宽度 |
|---|---:|
| Confirm / Alert | 576px 宽（B：根据 HiChat 参考图的实施映射） |
| 普通表单 Modal | 372px 宽，内容高度按 396 / 578 / 589 / 607px 变体取值（A） |
| 动态字段 / 插件 Modal | 711px 或 758px 宽变体（A） |

- 遮罩：`rgb(0 0 0 / 32%)`。
- Modal 背景：白色（A：Background/Body `#FFFFFF`）；圆角使用 Figma `Utilities/Border Radius/3XL` 语义 Token（A），CSS 数值为 B 实施映射。
- Modal 主体采用 Vertical Auto Layout；外层 Padding 32px、32px 圆角；主 Gap 使用 `Utilities/Spacing/7`（A）。
- Header、Content、Footer 的内部间距在不破坏 32px 外边距的前提下采用 B 实施映射。
- Footer：右对齐，按钮间距 10px；默认“取消”在左、“确认 / 保存”在右。
- 点击遮罩：普通信息 Modal 可关闭；有未保存内容的编辑 Modal 不得因误触遮罩丢失数据，应先弹放弃确认或不关闭。
- Esc：普通 Modal 可关闭；危险确认和未保存表单遵循同样的保护规则。
- 打开后焦点落在标题后的第一个可操作控件；关闭后焦点回到触发按钮。

### 6.9 Alert / Toast

- Toast 位于视口顶部居中，距顶部 24px。
- 最大宽度：360px；最小宽度：136px。
- Accent Alert：195×48px，Horizontal，Radius `XL`，上下 12px，左右 `Spacing/4`，Gap `Spacing/3`，Fill `#6E63FF` at 15%（A）。
- Text Alert：195×48px，Radius 12px，主文字 `#262626`，阴影 `0 12px 16px -4px #101828` at 4%（A）。
- Dropdown surface：195×48px，Radius 12px，0.5px 边框，背景 `#FFFFFF`，边框 `#F4F4F4`，同一阴影（A）。
- 成功使用绿色左边框，失败使用红色左边框。
- Toast 使用 12px 圆角、至少 48px 高、左右 16px 内边距；短提示按内容宽度展示（最小 136px，最大 360px），不能把单行提示拉满 360px。标题和正文均使用 14px 字号；仅有标题时不渲染空正文占位。
- 短反馈默认 4 秒后自动消失，不展示关闭叉；需要长期阅读或手动关闭的提示可显式开启关闭控件。
- Toast 用于短反馈，不承载必须阅读的长说明。
- 需要用户决定的内容使用 Alert / Confirm Modal，而不是 Toast。
- Toast 的位置、持续时间和成功 / 失败语义属于 P：产品决策；不得声称来自 Prototype 连线。

## 7. 交互同构规范

### 7.1 交互形态选择

| 形态 | 使用场景 | 导览后台动作 |
|---|---|---|
| 独立页面 | 多步骤、画布、持续编辑 | 新建 / 编辑导览任务、创建 / 编辑人设、地图点位编排 |
| Modal | 局部表单、一次性配置、危险确认 | 添加地图、添加插件、删除、放弃编辑、退出登录、重置 |
| Select / Popover | 选项较少、需要直接选择并回填 | 地图、人设等短列表 |
| Select Dialog / Modal | 需要搜索、分组或展示辅助信息 | 技能 / 插件等复杂选项 |
| Popover | 少量即时选项、更多操作 | 行更多菜单、添加任务类型、简单技能选择、账户菜单 |
| Toast | 成功、失败、处理中短反馈 | 保存成功、插件刷新、任务删除、同步提示 |

### 7.2 打开 / 关闭合同

#### Modal

1. 点击触发按钮打开。
2. 背景内容保持原位置，不重置表单草稿。
3. 取消、关闭按钮、Esc 按目标规则关闭。
4. 保存成功后先显示成功反馈，再关闭或跳转。
5. 点击遮罩是否关闭由 Modal 类型决定；未保存表单不可静默丢弃。

#### Popover

1. 点击触发按钮切换打开状态。
2. 点击外部或 Esc 关闭。
3. 选择项后立即更新当前上下文，并关闭（多选除外）。
4. 触发按钮保留 `aria-expanded`。

#### Select Dialog

1. 点击字段触发 Dialog。
2. 顶部显示标题和搜索框。
3. 列表项显示名称及必要的辅助信息。
4. 单选选择后回填并关闭；多选使用“完成”确认。
5. 没有结果显示空状态，不显示空白弹层。

### 7.3 必须统一的状态

- Hover：轻微表面变化，不改变布局。
- Focus：始终有可见 2px outline。
- Selected：文字加深 / 背景浅灰 / 勾选图标，三者至少保留两种信号。
- Disabled：降低对比度并阻止提交。
- Loading：按钮禁用，显示进行中反馈，防止重复操作。
- Error：控件红色边框 + 就近错误文案；不要只用颜色传达错误。
- Empty：说明当前没有数据并提供下一步动作。

## 8. 导览后台页面规范

### 8.1 导览任务列表

结构：

```text
页面标题：导览任务
说明：设置机器人要执行的导览内容
右侧：新建导览任务（Primary）
下方：Table
```

表格列：任务名称、地图名称、点位数量、创建时间、操作。

交互：

- 点击数据行进入任务详情。
- 点击“编辑”进入任务编辑流。
- 表头使用整行浅灰圆角容器；操作列与行内图标按钮居中对齐。
- “编辑”和红色删除图标直接展示，不把删除隐藏在“更多”菜单中。
- 删除使用 Confirm Modal。
- 无数据时使用 Empty state，CTA 为“新建导览任务”。
- 任务列表以 10 条为一页进行客户端分页；只有多页时显示“共 N 条”、页码与上一页 / 下一页，当前兼容全量列表接口，后续 API 迁移为 cursor 分页时保持同一交互。

### 8.2 地图列表与详情

- 地图列表复用任务列表的标题区、表格、操作列和空状态。
- “添加地图”使用 Modal 表单，包含名称和文件选择。
- 地图详情保留独立页面，因为包含预览区域。
- 预览区域使用明确边框和轻量圆角，不额外套多层卡片。
- 地图删除使用 Confirm Modal；删除成功显示 Toast 并回到列表。

### 8.3 人设列表与创建 / 编辑

- 人设列表复用 Table / Empty state / 居中的可见图标操作。
- 创建人设保留独立页面，复用 Figma 中 `创建人设2` 的表单区块结构。
- 表单区块：基础设置、问答设置、说话时调用技能。
- 返回按钮位于标题左侧。
- 取消 / 返回时若有未保存变更，使用放弃编辑 Confirm Modal。
- 问答设置仅包含可选提示词与可多选插件；不使用“表达规则”“关联插件”等非需求文案。
- “说话时调用技能”使用 Toggle，说明机器人可在说话时配合手势；当前不支持人设自定义技能。
- 新建 / 编辑人设、插件保留独立页面及表单卡片，并统一展示导览任务侧边导航；离开未保存表单时保留原有确认逻辑。
- “插件（可多选）”使用可勾选的自定义下拉框，默认 placeholder 为“请选择插件”，不使用浏览器原生多选框。

### 8.4 MCP 插件列表与添加 / 编辑

- 列表列：插件名称、工具数量 / 工具名称、创建时间、最后刷新时间、操作。
- 工具名称使用 Tag；超出列宽截断并提供详情查看。
- “刷新”、编辑、删除均使用居中的行内图标按钮；刷新完成后显示 Toast。
- 添加和编辑插件使用独立页面，字段纵向排列，底部操作保持可见。
- 动态认证字段根据认证方式出现，切换认证方式时保留可恢复草稿，不能静默清空已输入值。
- 保存插件需要显示处理中状态；初始化失败使用错误 Toast，并在必要时保留字段错误。

### 8.5 新建 / 编辑导览任务

保留三步独立编辑流：

1. 基础信息：名称、地图。
2. 点位：地图画布、点位新增、点位列表、排序、朝向。
3. 任务：抵达点位后 / 点位间路径上的语音播报、语音问答、执行技能。

交互调整：

- 第一步地图选择使用输入框下方的锚定 Select；选项只显示地图名称，选择后回填并关闭。
- 第二步地图缩放控件保留 Popover 之外的固定工具控件，因为它属于画布操作。
- 第三步“添加任务”使用 Popover 菜单。
- 技能选择使用分组 Modal，列表展示名称与版本，选中后通过“确定”回填。
- 语音人设选择使用自定义 Select / Popover，不使用浏览器原生 Select 作为最终视觉。
- 基础信息字段纵向排列，不使用并排双列。
- “设置任务”和“选择语音人设”是两张独立白色卡片。
- 底部操作区以独立白色卡片正常展示：上一步、下一步、取消、保存。
- 点位和任务拖拽排序保留；点位列表使用单一表头、无底色行和弱分割线。
- 点位列表为空时仅展示“暂无点位”，不展示表头；有数据时表头为“序号、名称、X 坐标、Y 坐标、朝向、操作”，采用 16px / 600 的字段标签规格，最后一行不展示尾部分割线。
- 地图 Select 未选择时使用 `#8A8A8A` placeholder 色；输入值与 placeholder 均为 16px。
- 任务段落的图标、主标题和“添加任务”文字按钮以主标题的垂直中心对齐；“添加任务”使用主题紫色。段落标题与首个字段、相邻字段之间均保留 16px 间距。
- 默认人设只在任务包含语音播报或语音问答时展示；没有语音任务且未选择自定义人设时，详情页不渲染人设区。
- 页面根节点保留稳定的垂直滚动条槽位，避免内容跨越视口高度时工作区横向抖动。

### 8.6 机器人监控任务详情

- 机器人上的任务按白底圆角卡片展示，名称与地图信息置于卡片内，进入与删除操作独立；“下发任务”按钮左侧显示加号。
- 从机器人导览任务列表进入详情后，地图上方仅显示一行“返回箭头 + 任务名称”；名称过长时省略，悬停可查看完整名称。返回箭头提供“返回任务列表”的悬停提示和无障碍名称。
- 左右顶部标题均使用 16px / 600，水平对齐；摄像头和地图保持等宽、16:9，不因流程展开而改变尺寸。
- 地图下方集中显示定位状态与定位操作，不再重复显示任务名称和“任务操控”标题。选点定位的提示、取消和确定按钮放在地图下方，避免遮挡可点击区域。
- 执行中、暂停中才显示执行状态提示；未开始和已结束时只保留可用操作，不显示闲置状态文案。
- 未开始和已结束时的主操作统一为“开始导览”。定位正常时仅显示弱化的“重新定位”图标，悬停说明操作；二次确认后状态恢复为未定位，再提供“一键定位”和“选点定位”。取消确认保留原状态；执行或暂停期间禁用重定位。
- 导览流程默认收起，刷新、切换任务或返回列表后再次进入均保持默认收起；展开或收起不影响导览执行。
- 展开后复用任务配置页的点位旗帜、路径箭头及动作类型布局，按“点位 → 路径 → 下一点位”分组，动作正文完整显示并自然换行。当前动作以主题紫色高亮，已完成动作使用完成标记。
- 流程及分组标题使用 16px / 600，与页面顶部标题一致；流程动作、展开操作、步骤数量、任务辅助信息及当前动作标记使用 14px。定位状态和主操作保持 16px，统一使用共享 Typography Token。窄屏允许正文自然换行，禁止缩小字号来塞入内容。

## 10. 响应式规范

### 1440px 及以上

- 页面左右边距 48px。
- 表格显示完整列。
- 复杂表单使用单列宽布局，最大内容宽度由页面容器约束。

### 1024–1279px

- 页面左右边距降为 32px。
- 表格允许横向滚动，不压缩到不可读。
- 标题区按钮保持可见，必要时按钮缩短文案但不隐藏主操作。

### 768–1023px

- 页面左右边距 24px。
- 语音二级导航可缩窄为 144px。
- Modal 使用 `calc(100vw - 48px)`，内部内容滚动。
- 底部固定操作栏按钮保持 44px 最小触达高度。

### 320–767px

- 一级导航允许横向滚动或折叠为菜单，但不能出现遮挡。
- 表格转为横向滚动容器，禁止强行挤压列内容。
- 表单单列显示。
- Modal 使用 `calc(100vw - 32px)`，最大高度 90vh，内容区滚动。
- 地图画布保持可缩放和拖拽；点位列表单独滚动。

## 11. 实施验收标准

### 视觉

- 页面背景、容器边距、导航高度、标题层级一致。
- Button、Input、Table、Modal、Alert、Empty state 的几何尺寸统一。
- 颜色、描边、分割线、圆角、阴影按 Token 使用。
- 所有控件显式设置字号、行高和字重。
- 图标保持同一线性 / 填充风格，不能随意替换成近似 glyph。

### 交互

- 同类操作统一使用 Modal、Popover、Select Dialog 或独立页面。
- Modal 支持取消、关闭、Esc、焦点回收和未保存保护。
- Popover 支持点击外部关闭和 Esc。
- Toast 不替代需要用户决策的 Alert。
- 表单错误靠近字段显示，提交按钮在 loading 时不可重复点击。
- 行点击与行内操作不互相误触发。

### 回归

- 一级导航切换。
- 任务列表行点击、编辑、删除。
- 地图添加、预览、删除。
- 人设创建、编辑、插件多选、放弃编辑。

## 12. 证据边界与产品决策

以下决策是 P：产品决策，不是 Figma Prototype 连线的直接复述：

1. 地图选择采用锚定 Select：列表项只显示地图名称，选择后要回填并关闭。
2. 添加 / 编辑插件采用独立页面：认证字段动态变化，页面表单可完整展示操作区并与旧版导览后台一致。
3. 创建 / 编辑人设保持独立页面：目标稿存在 `创建人设2` 页面样例，且导览业务字段较多。
4. 地图点位、拖拽排序、动作编排保持独立编辑页面：画布和持续编辑上下文不能被小弹窗破坏。
5. 删除、放弃编辑、退出登录、重置使用 Confirm Modal：这些操作需要用户明确决定，不能用短 Toast 替代。
6. 账户菜单、更多操作、添加动作、少量技能选择使用 Popover：选项少且选择后应立即回到当前上下文。

Prototype 已通过编辑器 Properties、画布截图、Prototype 演示页三种只读方式尝试；由于无障碍树没有暴露画布热点与连线目标，圆形连线细节记录为非关键来源风险，不作为本规范的实施前置条件。
